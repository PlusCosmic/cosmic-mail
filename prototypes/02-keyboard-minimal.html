@harry — opening this after debugging the sync engine overnight.

When the server closes the connection at the 25-minute IDLE ceiling, the SyncManager task logs the disconnect but never re-establishes IDLE, so the inbox stops receiving push updates until a manual sync.

Proposed fix: treat the timeout as a normal wakeup — re-run the envelope fetch for new UIDs, then re-enter IDLE — and only surface sync-state: error when the reconnect itself fails after backoff.

> On IDLE wakeup or 25-min timeout, re-sync. On error: retry with backoff (30s → 5m cap).
