@harry — opening this after debugging the sync engine on my machine overnight.

When the IMAP server closes the connection at the 25-minute IDLE ceiling, the SyncManager task logs the disconnect but never re-establishes IDLE, so the inbox stops receiving push updates until a manual Sync. Repro is reliable against imap.gmail.com.

Proposed fix: treat the timeout as a normal wakeup — re-run the envelope fetch for new UIDs, then re-enter IDLE — and only surface a sync-state: error when the reconnect itself fails after backoff.

> Loop: connect → LIST folders → UIDVALIDITY check → fetch new UIDs → IDLE.
> On IDLE wakeup or 25-min timeout, re-sync.

View it on GitHub or reply to this email directly.
